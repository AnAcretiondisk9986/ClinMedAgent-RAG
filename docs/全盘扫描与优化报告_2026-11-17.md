## 一、结论摘要

这一轮把项目从**"功能齐全，但每个请求都在白白付 200 ms"**、**"本地服务没有跨站防护"**、
**"流水线卡住就是永久卡住"**的状态，改到：

| 你会感觉到什么 | 之前 | 之后 |
| --- | --- | --- |
| 每检索一次（CLI / MCP / 网页） | 约 104 ms | **约 50 ms（-52%）** |
| 网页每点一次还要再加一次开库 | +230–280 ms | **+3 ms 左右** |
| 复合问题（"红肿热痛"这类多遍检索） | 约 1.3 秒 | **约 0.15 秒** |
| 索引库放在只读介质 / 只读属性上 | 直接打不开，`doctor` 报错 | **能打开检索，写操作报明确中文原因** |
| 查询里带引号 / 特殊字符 | 网页 500、CLI traceback | **正常返回** |
| 别的网页在你开着工作台时跨站触发 OCR | 可以 | **403 / 415 拒绝** |
| 流水线子进程卡死 | 任务永久 running、这本书永久锁死 | **阶段超时 + 杀进程树 + 回收** |
| 取消任务（非 Windows 平台） | 会把整个服务一起杀掉 | **只杀该阶段的进程组** |

**质量没有被牺牲**：44 个查询、每个取 top-8 的 `(chunk_id, score)` 在优化前后**逐位相同**
（含原书页码），全量测试从 249 条涨到 **289 条且全绿**。

### 3.1 检索性能（10 个医学问题 × 3 轮，4 本书 / 3463 块）

```
基线：    mean 104.3 ms   median 102.7 ms   max 176.2 ms
最终：    mean  50.2 ms   median  52.5 ms   max 114.3 ms      → -51.9%
```

### 3.2 打开索引库（网页每个请求的固定成本）

```
优化前：median 121.7 ms（DDL + 两轮 COUNT + 无条件写 user_version + WAL 提交）
```

`chunk_vectors` 无索引的计数 6 ms。

## 四、已实施的改动（按域）

### 4.1 检索内核（`library.py` / `qa.py` / `rerank.py`）

1. **打开索引库不再写盘**（单笔收益最大）：`_init_schema` 先读 `PRAGMA user_version`，版本相同就不写不提交；`PRAGMA foreign_keys = ON` 保留。回填行数改查 FTS5 影子表 `chunks_fts_ngram_docsize`（带旧 SQL 回退），`chunk_vectors(backend)` 补索引。
   → 开库 121.7 → 2.9 ms；同时修好只读介质打不开（原来 traceback 精确落在 `user_version` 写入）。
2. **打分循环重排**：命中门槛前移到最前（不命中的候选连二元组集合都不建）、`text.count()` 每 token 只算一次、`section`/`book` 规范化加缓存、只对最终参与重排的 200 条构造结果对象。
   *（收尾时把"每 token 只 count 一次"的实现从 dict 改回 list 语义——dict 会把重复概念合并、改变分数，实测 `DNA dna 复制` 的 top-1 会变。）*
3. **不再白取向量**：候选 SQL 不再 `LEFT JOIN chunk_vectors`（原来每题白传 1.76–2.01 MB 文本），改成按 `chunk_id` 对前 200 条二次取（`_vectors_for`）。
4. **遍数预算**：`build_search_queries(question, max_passes=4)`；选项合并遍**预留一格**（原来总被截掉，是死代码）；`_normalise` 加 `lru_cache`；空查询向量时重排不再逐条 `deserialize`。
5. **只读介质降级**：schema 迁移/回填在只读介质上失败时，不抛裸 `OperationalError`，改为 `readonly=True` + 中文 `warnings`；**二元组索引不完整时自动禁用 ngram 预筛、退回全表扫描**（否则中文 query 会静默 0 行）；写操作（`ingest`/`rebuild_*`）抛带说明的 `RuntimeError`。
6. **引用可靠性信号（零行为变化）**：每条证据新增 `coverage` / `matched_concepts` / `subject_matched`，供调用方复核，**不改排名、不改 `status`**（下一步门槛的依据，见 5.2）。

### 4.2 服务层与安全（`webapp.py` / `mcp_server.py`）

1. **[P0] HTTP 防护三件套**：`_host_allowed()`（只认本机名与绑定地址/机器名，防 DNS rebinding）、`_origin_allowed()`（有 Origin 或 `Sec-Fetch-Site` 时**按 scheme+host+port 完全同源**，不是只比主机名）、变更类接口要求 `Content-Type: application/json`（上传例外）。
2. **常驻 `Library`**：按线程持有连接（`threading.local`），请求结束不关闭；`Handler.finish()` 在连接结束时回收，跨线程收尾只"登记"不假关闭（`request_close()`），真关闭交给 owner 线程。原来每请求都要跑一遍 DDL + 回填 + 写盘，还顺带消掉了"重建索引期间整站读接口 30 秒后 500"。
3. **非 ASCII 访问令牌**：`compare_digest` 比较前统一 `encode("utf-8")`（原来中文口令 100% 不可用）。
4. **预览图缓存可控**：渲染宽度量化到 `900/1200/1600/2000/2600` 五档，缓存超过 `MEDICAL_RAG_WEB_CACHE_MAX_MB`（默认 256 MB）按 mtime 淘汰。原来一页可按任意宽度无限攒（实测 175 张 / 71.5 MB / 26 种宽度）。
5. **MCP 健壮化**：非法 JSON、非对象报文、库打不开都不再让进程退出，改回 JSON-RPC 错误；`limit: null` 正常处理。
6. **Range 与状态码**：`bytes=-N` 由错误的 416 改成 206 尾部字节；非法 Range 按 RFC 忽略；超限体 413、坏 JSON/非对象 400（原来都是 500）。

### 4.3 前端（`webui/app.js` / `index.html` / `style.css`）

1. **滑块去抖 + 宽度档位**：`input` 150 ms 去抖、`change` 立即刷新，与服务端同一组五档宽度。原来每拖一格就渲染一张 2600 px PNG。
2. **侧栏不再每 1.2 秒全量重建**：按渲染消费字段算签名，相同直接返回；重建前保存、重建后恢复滚动位置与焦点。
3. **详情页过期校验**：后台任务完成的回调不再把详情/页码切回上一本书。
4. **超时与可取消**：`AbortSignal.timeout(15s)`、上传 XHR 超时与取消按钮、刷新失败不再假装"已刷新"、轮询移到首个 `await` 之前（原来首个请求挂住就永不再轮询）。
5. **四个死控件接线**：复制页文本、原书页号、返回检索、检索结果计数。
6. **可读性**：手动暗色 + 系统亮色不再白底白字；正文栏宽度接回 `--text-width`，窄屏不再裁行尾。

### 4.4 流水线与诊断（`pipeline.py` / `tasks.py` / `doctor.py` / `workspace.py` / `tools/*`）

1. **子进程生命周期**：按阶段超时预算（`ocr` 按页数放大，可用 `MEDICAL_RAG_STAGE_TIMEOUT_<STAGE>` 覆盖）、stdout 读线程 + 队列让取消能穿透管道、Windows `taskkill /T /F` 杀进程树、`finally` 回收句柄；**POSIX 加 `start_new_session=True`**（否则 `killpg` 会杀掉服务自己）。
2. **诊断真只读**：`doctor` 自检与 `load_db_books` 走 `mode=ro`，失败回退 `immutable=1`，带哨兵查询；只读介质上不再报 error/503。
3. **缓存指纹**：渲染/版面/表格缓存目录名并入 PDF `size/mtime`，命中校验 meta（同目录换 PDF 不再复用旧页图）。
4. **产物原子写 + 续跑容错**：新增 `tools/tools_common.py`（`atomic_write_text` / `valid_page_json` / `cached_render`），OCR/版面/表格/纠错四个脚本改为"临时文件 + `os.replace`"，续跑前校验 JSON，坏页记入 `corrupt_pages` 而不是让整本崩掉。
5. **测试鉴别力**：doctor 只读分支真断言、临时根目录、健康检查收紧。

## 五、只能推迟的事（附实测理由）

审计 61 条（P0×1 / P1×16 / P2×31 / P3×13），本轮修掉 23 条（含唯一 P0、16 个 P1 中的 13 个）+ 复核新增 13 条。
以下是**有意不做**的，理由写清楚，避免下一轮重踩：

### 5.1 章前页永远进不了索引（内容缺口，P1）

实测每本真书丢掉 PDF 第 1–24 页（封面、内容简介、序、目录、绪论）。
**为什么不改**：需要改分章逻辑并**重跑真实教材**的 `text → index`，属于数据重建而不是代码修补；
而且会改变 chunk 划分与排名，必须在你确认后单独做。这是下一轮最值得做的内容类改进。

### 5.2 `evidence_found` 没有相关度下限（假引用，P1）

对使用者伤害最大的问题：语料外的问题也会拿到教材页码。本轮实测（32 题）：

```
语料内正确给出依据：19/20
语料外误报证据：    8/12    ← 其中"化疗药物导致的中性粒细胞减少"引到了《毛概》
```

**为什么本轮不改**：先验证了"能不能安全地加门槛"，结论是**现有信号不足以设阈值**：

| 候选规则 | 实测结果 |
| --- | --- |
| `coverage >= 0.5` | 会把 4 道真题（心传导/动作电位/细胞膜/炎症）误判成"无依据"，同时仍放过语料外题 |
| `score` 阈值 | 语料内最低 6.38、语料外最高 10.32，**区间重叠**，不存在干净阈值 |
| `subject_matched` | 语料内 19/19 True，语料外也有 4/12 True，单独用会漏判 |

本轮已把 `coverage` / `matched_concepts` / `subject_matched` 暴露到证据里（零行为变化）。
**建议的下一步**：加"问题词是否存在于语料词表"（doc-frequency）信号——"阿司匹林""Ranson 评分"
这类词在四本教材里根本不出现，这是最干净的判据；再用 ≥40 题金标集（≥1/3 语料外）定阈值，
最后才改 `status`。属医学结论口径变更，建议你亲自拍板阈值。

### 5.3 其它明确推迟项

| 事项 | 原因 |
| --- | --- |
| 短拉丁词按词边界匹配（`st` 会命中英文单词内部，612/3463 块） | 会改变 `matched` 集合进而改分数，与"分数逐位不变"的验收冲突；留待金标集就绪后单独做 |
| `outputs._commit` 落盘逆序 | 改动会打破一条既有回滚用例（`RollbackFailureTests`），需同时重写故障注入点；已回滚为原样，建议下一轮连测试一起改 |
| CSS 五代主题分层重构 | 需人工逐屏视觉回归，不适合无人值守批量改 |
| `book` 范围解析在 4 个入口各写一套 | 统一会牵动 CLI 退出码语义，需单独评审 |
| `bridge` 每条请求重开书库 | 收益为 0（CLI 级工具） |
| MCP 错误码精确化（`-32700` / `-32600`） | 现在"不崩、报文合法"，只是码不精确，P3 |
| 真正"目录也不可写"的只读介质 | 需要改 ACL 才能验证；`open_readonly` 的 `immutable=1` 分支覆盖该场景，本轮只验证了它存在且能读 |
